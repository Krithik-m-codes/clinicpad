# ClinicPad — Data Model

**Status:** proposed
**Database:** PostgreSQL 16 (Supabase, Mumbai)
**ORM:** Drizzle
**Tenancy:** `tenant_id` on every clinical/business table, enforced by RLS

---

## 1. Conventions

- Primary keys: `uuid` (UUIDv7 generated by the app).
- Timestamps: `timestamptz`, UTC. Display in the clinic's timezone (`Asia/Kolkata` default).
- Money: `bigint` paise + `char(3)` currency. Never floats.
- Soft delete: `deleted_at timestamptz`; hard delete only via retention jobs or explicit legal erasure.
- Audit columns: `created_at`, `created_by`, `updated_at`, `updated_by`.
- Clinical records are versioned, not overwritten.
- Every table with patient data has `tenant_id` and an index `(tenant_id, ...)`.
- Enums are Postgres enums or lookup tables; prefer lookup tables for values that clinics may customise.

---

## 2. Core entity map

```
tenants (clinics)
  ├─ branches
  ├─ memberships ── users
  ├─ doctors (profile extension of membership)
  ├─ patients
  │    ├─ patient_consents
  │    ├─ appointments
  │    ├─ visits / encounters
  │    │    ├─ vitals
  │    │    ├─ diagnoses
  │    │    ├─ prescriptions ── prescription_items
  │    │    ├─ investigations
  │    │    └─ documents
  │    ├─ invoices ── invoice_items ── payments
  │    └─ messages
  ├─ templates ── template_versions ── template_fields
  ├─ services
  ├─ formulary_items
  └─ audit_events

subscriptions ── plans
feature_flags
sync_outbox (client-side, mirrored for diagnostics)
```

## 4. RLS policy pattern

```sql
-- Helper: current tenant from JWT
create or replace function current_tenant_id() returns uuid
language sql stable as $$
  select nullif(auth.jwt() ->> 'tenant_id', '')::uuid
$$;

-- Apply to every tenant table
alter table patients enable row level security;

create policy tenant_read on patients
for select using (tenant_id = current_tenant_id());

create policy tenant_write on patients
for insert with check (tenant_id = current_tenant_id());

create policy tenant_update on patients
for update using (tenant_id = current_tenant_id())
with check (tenant_id = current_tenant_id());
```

Branch scoping adds:

```sql
and (branch_id is null or branch_id = current_branch_id())
```

Role checks use a `current_role()` helper backed by `memberships`.

**CI requirement:** a test suite signs in as tenant A and asserts zero rows from tenant B across every table.

## 5. Indexing and performance

- Every tenant table: `(tenant_id, created_at desc)`.
- Patients: `(tenant_id, phone)`, trigram on `full_name`.
- Appointments: `(tenant_id, branch_id, scheduled_start)`, `(doctor_membership_id, scheduled_start)`.
- Visits: `(tenant_id, patient_id, started_at desc)`.
- Prescriptions: `(tenant_id, patient_id, created_at desc)`, unique `(tenant_id, rx_number)`.
- Audit: `(tenant_id, created_at desc)`, `(tenant_id, entity_type, entity_id)`.
- Messages: `(tenant_id, status, created_at)`.
- Use partial indexes for `deleted_at is null` where appropriate.
- Analytics queries use covering indexes or a materialized view refreshed periodically.

## 6. Retention and deletion

| Data | Retention |
|---|---|
| Clinical records | Per local law; India: long-term (typically 3+ years, often longer for medico-legal safety). Default: retain until tenant deletion + legal hold. |
| Audit logs | 7 years (configurable) |
| Messages | 24 months |
| Documents | Until patient/tenant deletion or retention expiry |
| Backups | 30 days rolling + monthly for 12 months |
| Deleted patients | Soft delete 30 days, then hard delete unless legal hold |

Deletion workflow: request → verify identity → check legal hold → export → delete/anonymise → audit event → confirmation.
